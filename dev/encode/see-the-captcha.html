The ENCODE CAPTCHA, actually presented

Every discussion of this problem so far has been about a 405 status and an x-amzn-waf-action: captcha header. But there is a real, human-facing CAPTCHA behind those — an AWS WAF "Human Verification" page with an actual puzzle widget. This page puts it on your screen.

The URL being requested is an ordinary ENCODE bigWig, the kind any igv.js track config would point at:

Use a private/incognito window. Once you solve a WAF challenge, AWS stores an aws-waf-token for the host and waves you through for a while — so on a second visit you may get the file instead of the puzzle. A fresh private window is the reliable way to see it. If you get a file download rather than a challenge, that is what happened.

1. Click through to it directly

This is a plain top-level navigation — no igv.js, no JavaScript, no Origin header at all. The WAF challenges it purely because the request comes from something that looks like a browser. Opens in a new tab.

Open the ENCODE file in a new tab

2. Or watch it render right here

The challenge response sets no X-Frame-Options and no framing CSP, so it will render inline. Click below and the AWS WAF puzzle loads in the frame — the same widget, live from captcha.awswaf.com. You can actually solve it.

3. What igv.js gets instead of your data

This is the point of the whole exercise. When a bigWig reader issues its range request, this HTML is the response body — served where the first bytes of a binary file should be. The reader has no idea it is looking at a CAPTCHA page; it tries to parse it as a bigWig header, finds a bad magic number, and reports something unrelated to what actually happened.
